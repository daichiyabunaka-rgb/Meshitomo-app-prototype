# めしとも（Meshitomo）

**趣味でつながる。顔ではなく中身で。** 同じ趣味の飯ともを「今から・近くで」探すスマホアプリのプロトタイプです。

ビジネスモデルは「一般ユーザー完全無料 × ビジネスユーザー（店舗）有料」。店舗向けの有料機能として **AI接客**（LLMによる来店前対応）と **地図連携** を提供します。クーポン配信型ではなく、店舗が応対リソースを削減できる機能で課金する方針です。

## コンセプト（設計原則）

| 原則 | 内容 |
|---|---|
| 顔画像禁止 | アイコンは料理写真・趣味画像のみ（AI顔検出による自動審査は本開発で実装） |
| 恋愛目的禁止 | 趣味仲間探しに特化。規約とモデレーションで排除 |
| 時限募集 | 募集は1〜3時間で自動消滅。「今から」感を出会い系化防止に使う |
| 距離は粗表示 | 位置は「〜1km / 1〜3km」のバンド表示のみ。生の緯度経度は保持しない設計 |

## 機能（プロトотип）

- メール会員登録 / ログイン / ログアウト（端末内モック認証、セッション永続化）
- GPS位置情報取得 → 近くの募集 / 一般ユーザー / 店舗（ビジネスユーザー）を一覧
- 募集（1〜3時間の時限）→ 応募 → 承認 → グループチャット自動生成
- 1:1のDM
- アイコン画像の投稿（ギャラリー / カメラ、端末内永続化）
- 近くの店マップ（OpenStreetMap。APIキー不要）+ Googleマップで開く
- AI接客チャット（デモはルールベース。店舗タイプごとの口調）

## 実行方法

```powershell
flutter build apk --release    # APK ビルド
```

テスト: `flutter test` / 静的検証: `flutter analyze`

## 本開発への移行計画

1. **Supabase**: `docs/supabase_schema.sql` を適用し、`AuthService` / データ層を Supabase（Auth / Postgres+geohash / Realtime / Storage）に差し替え
2. **AI接客**: ルールベースのモックを LLM API に置換（店舗情報 + 口調設定をプロンプトに渡す）
3. **モデレーション**: アイコン画像の AI 顔検出、禁止ワード審査
4. **地図**: 必要に応じて Google Maps SDK（APIキー）に移行し経路案内を表示
